03 / PIPELINE

How a scan actually runs

  1. 01

    Validate, never visit

    The URL is parsed and length-checked. The scanner never resolves or requests the host.

  2. 02

    Extract structural signals

    Dots, hyphens, digits, special characters, scheme, IP hosts, subdomains, and login wording.

  3. 03

    Score and record

    The model returns a class and a phishing probability, written to the scan database with a timestamp.

  4. 04

    Review in the console

    The dashboard aggregates URL, file, and email events, with CSV export for reporting.

READ THIS FIRST

What this is not

PhishGuard is an educational triage tool, not a security product. The model can be wrong in both directions, file scanners only report known signatures, and a low score is not proof of safety. Do not use it as your only control.

  • URLs are never fetched or screenshotted.
  • Email authentication headers are reported claims, not verified signatures.
  • Third-party submission is opt-in per scan.
  • Hosted demo storage can be reset on redeploy.
