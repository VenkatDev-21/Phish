Four top-level `unittest.TestCase` suites (`DashboardTests`, `EmailSecurityTests`, `FileScanningTests`, `HardeningTests`) each import the live Flask app via `import app as web_app` and drive it through `web_app.app.test_client()`. Tests share a common bootstrap pattern: create an in-memory `tempfile.TemporaryDirectory`, point `DATABASE` and `UPLOAD_DIR` at subpaths of that directory, call `web_app.init_db()` to build SQLite tables, then obtain a CSRF token by visiting a page and reading `session['_csrf_token']`. External I/O (DNS lookups, ClamAV subprocess calls, VirusTotal/OPSWAT HTTP requests, ML model prediction) is stubbed with `unittest.mock.patch` / `patch.object` / `patch.dict` so tests remain deterministic. Database state is inspected directly via `web_app._connection()` context manager using raw SQL against SQLite tables (`scans`, `email_scans`, `file_scans`). There is no test runner configuration file — each module ends with `if __name__ == "__main__": unittest.main()` and can be executed individually or via `python -m unittest discover tests`.
