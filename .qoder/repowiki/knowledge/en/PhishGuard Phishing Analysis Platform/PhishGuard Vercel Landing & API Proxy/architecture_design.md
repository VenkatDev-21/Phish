Two-layer deployment on Vercel with no build step (`framework: null`, `buildCommand: null` in vercel.json).

- Static assets: `index.html`, `styles.css`, `favicon.svg`, and `app.js` are served as-is. The HTML is a single-page marketing + demo shell; all DOM wiring lives in `app.js`, which queries elements by `data-*` attributes (e.g. `data-scan-form`, `data-result-badge`) rather than class names.
- Serverless API routes under `api/`: `health.js` reads `PHISHGUARD_APP_URL` from environment variables and proxies GET `/api/v1/health` to the upstream Flask app, returning a friendly 200 even when the backend is cold or missing. `scan.js` accepts POST JSON `{ url }` and forwards it to `${appUrl}/api/v1/scan/url`, passing through the upstream status code and body so the frontend sees only same-origin responses — this avoids CORS and keeps the Render hostname secret.
- Routing and security headers are declared in `vercel.json`: CSP restricts scripts/styles/connect to `'self'`, API routes get `Cache-Control: no-store`, and static assets get 1-hour cache. Each function has a 15-second max duration, with an additional 8-second AbortController timeout inside `scan.js` for the upstream call.
- Dependency direction is one-way: the browser talks to `/api/*`; those functions call the external backend via `fetch`. There is no shared library between them — each handler independently reads `process.env.PHISHGUARD_APP_URL` and strips trailing slashes.
