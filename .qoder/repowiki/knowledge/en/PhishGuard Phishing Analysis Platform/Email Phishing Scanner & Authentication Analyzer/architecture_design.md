Three cooperating modules form a layered scanner pipeline:
- `email_security.py` is the orchestrator: it parses `.eml`/`.txt`/`.html` input via Python's `email.parser`, walks MIME parts to collect plain text, HTML, headers, and attachments, then aggregates findings across categories (`authentication`, `sender`, `content`, `html`, `urls`, `attachments`, `reputation`) into a single risk score and verdict.
- `email_auth.py` provides pure DNS/authentication utilities: it parses `Authentication-Results` / `Received-SPF` / `DKIM-Signature` headers with regex, resolves public DNS records (TXT/MX/A/NS) via `dnspython`, and compares registrable domains using `tldextract` to determine SPF/DKIM alignment under both relaxed and strict DMARC policies.
- `email_attachment_analysis.py` inspects attachment payloads locally: it identifies file types by magic bytes, extracts text from ZIP/Office packages, PDFs, and images, scans archives against size/member/compression-ratio limits, and delegates sandboxed scanning to `file_analysis.analyze_file`.

Dependency direction is one-way: `email_security.py` imports both `email_attachment_analysis.analyze_attachment` and `email_auth.analyze_authentication` / `domains_aligned`; the other two files have no intra-module dependencies. External ML scoring is optional — `url_model` is passed in and wrapped by `_model_prediction`, which falls back gracefully when feature names do not match or the model is unavailable.
